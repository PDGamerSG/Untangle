# Expand Untangle by proving why code changed

Untangle should grow into the **verified, time-aware decision layer for software**: the system that shows why code is the way it is, what has changed upstream since that reason was given, and says so plainly when it does not know. It should not become one more cited code-Q&A tool, because that tier is already sold by Unblocked for **$29 per user per month** with MCP, Slack, PR review and meeting ingestion ([Unblocked pricing](https://getunblocked.com/pricing/index.md)). No competitor found in this research documents refusal, models decisions as time-versioned objects with supersession, or links a past decision to the upstream changelog, advisory or issue that motivated it. The internet-research subsystem should therefore start with **free, structured sources** (OSV.dev, deps.dev, endoflife.date, GitHub issues, releases and compare, CISA KEV, EPSS) fetched by the GitHub Actions worker. Open web search comes last and stays tightly bounded. On the configured Haiku 5.5 model, a quick investigation costs roughly **5 to 9 cents**, most of it the $10-per-1,000 search fee, as long as no request crosses the 100k-token price step ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Citations have to stay machine-checkable. Web evidence should reach answers only as fetched text or self-supplied `search_result` blocks, never as encrypted search snippets, and the step that reads web pages should never see private evidence or hold tools. The first wedge is decision context for coding agents through MCP, paired with a checkable "can we remove this workaround or pin?" feature. Two cheap moves support it: turning on rationale extraction, which costs cents per import, and a much larger eval. Handover for Indian IT services and compliance evidence packs come after accounts and tenancy exist. The roadmap has three phases: two weeks to prove the differentiators with numbers, one to two months to ship the external-evidence wedge and the table stakes, and three to six months to become a multi-tenant product.

## Unblocked sells cited answers for $29; nobody sells verified, time-aware why

The closest direct competitor is **Unblocked**. It calls itself the context layer for agentic software development. It ingests code, PRs, CI, Jira and Linear, Confluence, Notion, Slack, Teams, the meeting tools Fireflies and Granola, Datadog and Sentry, and selected "external websites". Its answers link to the files, PRs, tickets or docs they used, and it advertises "reference obsoletion" and conflict resolution across sources ([Unblocked AI info](https://getunblocked.com/ai-info/index.md)). It runs on web, macOS, Slack and Teams, MCP, a CLI, an Answers API and PR review. Its Enterprise tier adds SSO, permission enforcement ("Data Shield") and on-prem deployment ([Unblocked pricing](https://getunblocked.com/pricing/index.md)). It is funded, having raised a **$20M Series A** in May 2025 ([TechCrunch](https://www.techcrunch.com/2025/05/06/unblocked-raises-20-million-for-its-ai-assistant-to-help-devs-understand-legacy-codebases)), and its entry price rose **53%** in September 2026 when it dropped its $19 tier ([PricingSaaS](https://pricingsaas.com/companies/unblocked)). Cited "why" answers delivered over MCP are therefore a priced product category, not a moat.

Four adjacent clusters surround it, and each covers part of the space while leaving the same hole. Auto-generated wikis explain *what* code does from the current snapshot. DeepWiki's MCP server is free and unauthenticated for public repos ([Cognition](https://cognition.ai/blog/deepwiki-mcp-server)), and Google Code Wiki regenerates after every change ([Google Developers Blog](https://developers.googleblog.com/en/introducing-code-wiki-accelerating-your-code-understanding/)). Context engines for agents have made MCP universal: Augment's Context Engine became available as an MCP server in February 2026 ([Augment](https://augmentcode.com/blog/context-engine-mcp-now-live)), Qodo exposes a `deep_research` tool across repositories ([Qodo docs](https://docs.qodo.ai/developer-tools/context-engine-mcp-tools)), and Sourcegraph sells Deep Search from a $16K-a-year Enterprise floor ([Sourcegraph pricing](https://sourcegraph.com/docs/pricing)). Review bots such as Greptile build "learnings" from past PRs ([Greptile pricing](https://www.greptile.com/pricing.md)). CodeScene's off-boarding simulator flags low-bus-factor areas statistically, not from rationale ([CodeScene docs](https://codescene.io/docs/guides/simulations/offboarding-simulator.html)). A new 2026 category captures "why" *going forward* for agent-written code. Entire Checkpoints attaches agent transcripts to commits through a trailer ([Entire docs](https://docs.entire.io/guides/checkpoints/overview)). Cursor published Agent Trace, a draft spec for line-level AI attribution ([InfoQ](https://www.infoq.com/news/2026/02/agent-trace-cursor)). GitHub Copilot Memory stores repository facts with code citations, revalidates them against the current branch and deletes unused memories after 28 days ([GitHub docs](https://docs.github.com/en/copilot/concepts/agents/copilot-memory)). Untangle reconstructs "why" *backward* for legacy, human-written code. The two directions complement each other, and agent-provenance trailers can become another Untangle evidence type.

Three capabilities are missing everywhere. The first is explicit abstention: no vendor in the competitor survey documents refusing when evidence is missing. The second is formal temporal modelling. Copilot Memory's expiry and Unblocked's "obsoletion" come closest, and neither exposes supersession chains or validity windows. The third is time-aligned external evidence. CodeRabbit runs web queries during reviews to pull current documentation ([CodeRabbit docs](https://docs.coderabbit.ai/changelog/code-graph-analysis)), and Renovate embeds upstream release notes in dependency PRs ([Renovate docs](https://docs.renovatebot.com/key-concepts/changelogs)). Neither uses external sources to explain a *historical* decision. Lacking that awareness has a visible cost: Code Wiki failed to flag that the vuejs/vue repository is end-of-life, and was only "half right" on a question where it ignored Microsoft's own documentation ([The Register](https://www.theregister.com/2025/11/17/google_previews_code_wiki/)).

User complaints line up with Untangle's design. Maintainers report confidently wrong generated docs: Scala contributors said most details in their DeepWiki pages were wrong ([Scala contributors](https://contributors.scala-lang.org/t/ai-slop-claiming-to-be-documentation/7382)). An academic study of CodeRabbit comments in the wild found many false-positive, redundant or out-of-scope suggestions ([alphaXiv 2607.03316](https://www.alphaxiv.org/abs/2607.03316)). Pricing keeps changing: Greptile switched pricing models several times in 2026 ([Greptile v4](https://www.greptile.com/blog/greptile-v4)). Self-hosting is reserved for Enterprise tiers. Validated citations alone are not unique, though. A May 2026 hackathon entry strips any claim whose commit SHA is missing from `git log` ([lablab.ai](https://lablab.ai/submissions/shwuqbtppeztzs0t82h5850k)). The defensible ground is the *combination* summarised below.

| Capability | Untangle today | Strongest competitor coverage | Implication |
|---|---|---|---|
| Cited answers about history | Yes; citation IDs must be in retrieved evidence and two-or-more-digit numbers grounded | Unblocked, Copilot Memory, Code Wiki hyperlinks | Parity, not moat |
| Decisions as time-versioned objects with SUPERSEDES | Yes (`valid_from`/`valid_to`, `created_at`/`expired_at`) | None documented; Unblocked "reference obsoletion" | Core moat; publish as-of-date accuracy |
| Documented refusal | Yes, fixed wording | None found | Publish a measured refusal rate |
| Handover call vs code CONFIRMS/CONTRADICTS, Hinglish | Yes | Unblocked ingests Fireflies/Granola; no code-mixed support found | Wedge for Indian IT services |
| Rationale-based risk radar | Pulse (five boolean signals) | CodeScene off-boarding (statistical) | Differentiator once signals are method-backed |
| Time-aligned external evidence per decision | None | CodeRabbit web search for reviews; Renovate changelogs | Open gap |
| MCP, PR bot, Slack, ticket/doc connectors | None | Nearly every competitor | Table stakes to build |
| SSO, tenancy, private repos | None (public repos, shared evidence) | Enterprise tiers everywhere | Prerequisite for revenue |

The positioning follows from this table. Untangle is decision memory that proves why, shows when that reason stopped being true, and says when it does not know. It should lead with two numbers no competitor publishes: refusal precision and as-of-date accuracy. Website copy should describe these capabilities without naming the model or provider, as the project rules require.

## Agent context and dependency rationale lead eleven ranked use cases

The "why" problem has independent measurements. A field study of 78 professional developers found **about 58% of developer time goes to program comprehension** ([Xia et al., TSE 2018](https://xin-xia.github.io/publication/TSE17.pdf)). Stack Overflow's 2024 survey headline says 61% spend more than 30 minutes a day searching for answers, although its own chart values sum to 63.8% ([Stack Overflow 2024](https://survey.stackoverflow.co/2024/professional-developers)). Atlassian's 2025 survey ranks "finding information" as the top time-waster, with 50% of developers losing 10+ hours a week ([Atlassian 2025](https://www.atlassian.com/blog/developer/developer-experience-report-2025)). AI has moved the complaint rather than removed it. **65% of developers report correcting AI work that "missed the original intent"** ([SD Times on Atlassian 2026](https://sdtimes.com/developer-experience/61556/)), 65% of developers using AI for refactoring say it "misses relevant context" ([Qodo 2025](https://www.qodo.ai/reports/state-of-ai-Code-quality/)), and 87% are concerned about agent accuracy, which leads Stack Overflow to advise leaders to "focus on your data first" ([Stack Overflow 2025 leaders](https://stackoverflow.co/internal/resources/2025-stack-overflow-developer-survey-for-leaders/ai-agents/)). The pain is concentrated, not universal: 29.6% hit knowledge silos 10+ times a week while 52.1% never do ([Stack Overflow 2024](https://survey.stackoverflow.co/2024/professional-developers)). The buyer is the team where knowledge sits with a few people, such as legacy estates, high-attrition delivery centres and outsourced systems.

Ranking by market pull alone would put audit evidence third. Ranking by what Untangle can ship first, with no accounts and only public repos, moves dependency and workaround rationale up, because it reuses lockfile diffs Untangle already ingests and every claim can be checked against an upstream API. The table uses that build-order ranking and keeps the market-pull evidence visible.

The ranking rests on three judgements. First, use case 2 is commodity only when it stands alone. A CVE feed is everywhere; a statement such as "we pinned X because of upstream issue #123, which closed as completed and shipped in 2.4.0" exists nowhere else. It also matters more because public vulnerability analysis is thinning: only **28% of 2025 CVEs were fully analysed by NVD** ([Zafran](https://www.zafran.io/resources/the-2025-spike-in-vulnerabilities-isnt-the-full-story)), and fewer than 9.5% of vulnerabilities are reachable at function level ([Endor Labs](https://www.endorlabs.com/lp/2024-dependency-management-report)). Second, handover is Untangle's most distinctive wedge. Notice periods of 90 days are justified explicitly as knowledge-transfer time ([Analytics India Magazine](https://analyticsindiamag.com/report-notice-periods-in-india-it/)). India has 2,117 GCCs employing 2.36M people ([Zinnov–Nasscom](https://zinnov.com/centers-of-excellence/zinnov-nasscom-india-gcc-landscape-2026-report/)). Formal, documented KT measurably improved offshore engineers' understanding where informal discussion did not ([BCS on Williams 2010](https://www.bcs.org/articles-opinion-and-research/a-steep-learning-curve/)). TCS's 13.3% attrition alone implies roughly 80,000 departures a year, a calculation rather than a reported figure. Third, audit evidence has the largest budgets but the heaviest prerequisites. The CRA's reporting obligations went live on **11 September 2026** with 24-hour and 72-hour clocks, and its technical-documentation duties apply from **11 December 2027** ([European Commission](https://digital-strategy.ec.europa.eu/en/policies/cra-reporting)). Auditors sample SOC 2 changes for approved requests that state a reason ([soc2auditors.org](https://soc2auditors.org/insights/soc-2-change-management-controls/)). All of this needs private repos, tickets and approvals, so it belongs in phase 3. On price, per-seat anchors sit at about $20–35 a month (Unblocked $29, Sourcegraph Starter $19 per [Sourcegraph](https://sourcegraph.com/docs/pricing/enterprise)). Competitors that meter usage keep repricing, which suggests a predictable per-repository or per-transition plan as a differentiator, especially in India, where per-seat dollar prices look high against salaries. That is an inference that needs pilot validation.

## External evidence should start with free structured APIs, not web search

The subsystem should answer a fixed set of upstream questions for each Decision. Is the pinned version affected by an advisory, and which version fixes it? Has the upstream issue a workaround waits on been closed, and did the fix ship in a release? Is the runtime past end-of-life? Has the package been deprecated or yanked, and is it still maintained? Is a cited link dead, and where is its archived copy? Most of these have deterministic answers from free, structured APIs. LLM web search is needed only to *discover* links nobody recorded. Three design rules follow. External evidence is a separate trust tier and never silently overrides repo evidence. Every external fact is aligned to the Decision's `valid_from` (what upstream said *then*) and to its fetch time (when Untangle learned it). An LLM synthesis step runs only after deterministic joins have done what they can.

### Structured sources answer most upstream questions at zero API cost

**OSV.dev** should be the primary vulnerability source. It needs no key, its docs state "Currently there are no limits on the API", it offers `querybatch` and bulk dumps, and its records carry machine-readable `introduced`/`fixed` events ([OSV API](https://google.github.io/osv.dev/api/)). Its `querybatch` returns only IDs and `modified` timestamps, so a sync can diff timestamps and fetch full records only for changed IDs ([OSV querybatch](https://google.github.io/osv.dev/post-v1-querybatch/)). OSV IDs (GHSA, PYSEC, GO, RUSTSEC) do not depend on CVE assignment, which matters because the MITRE contract that keeps CVE running was extended only to 16 March 2026 and later funding is confirmed only by secondary sources ([The Record](https://therecord.media/cisa-extends-cve-program-contract-with-mitre)). **deps.dev** is the cross-ecosystem metadata backbone. It returns deprecation, licences, advisory keys, source repo and an embedded Scorecard. It "expressly permit[s]" caching, its generated data is CC-BY 4.0 ([deps.dev v3](https://docs.deps.dev/api/v3/)), and its batch endpoints take up to 5,000 items ([deps.dev v3alpha](https://docs.deps.dev/api/v3alpha/)). The native registries fill in what deps.dev normalises away. The npm `deprecated` string often embeds the upstream issue URL ([npm registry probe](https://registry.npmjs.org/request)). PyPI exposes `yanked_reason` and has no edge rate limit, though it asks for a unique User-Agent ([PyPI API](https://docs.pypi.org/api/)). crates.io requires an identifying User-Agent and one request per second ([RFC 3463](https://rust-lang.github.io/rfcs/3463-crates-io-policy-update.html)). The Go proxy maps a version to its exact tag and commit ([Go proxy](https://proxy.golang.org/)).

| Order | Source | Upstream question it answers | Access and limits | Runs in |
|---|---|---|---|---|
| 1 | OSV.dev `querybatch`, `/vulns/{id}` | Is this version affected; which version fixes it? | No key; "no limits" stated | Worker batch; single `query` allowed inline |
| 2 | deps.dev v3 and v3alpha batch | Deprecated? Licence? Source repo? Scorecard? Dependents? | No key; caching permitted; batch ≤5,000 | Worker; single `GetVersion` allowed inline |
| 3 | npm, PyPI, crates.io, Go proxy | Deprecation text, yank reason, retractions, version→tag | No key; crates.io 1 req/s with User-Agent | Worker |
| 4 | endoflife.date API v1 | Runtime or framework EOL, LTS, latest patch ([OpenAPI](https://endoflife.date/docs/api/v1/openapi.yml)) | No key; MIT | Worker daily with ETag |
| 5 | GitHub issues, timeline, releases, compare | Upstream issue closed? Fix contained in which tag? Release notes? | `GITHUB_TOKEN` 1,000 req/h per repo; anonymous 60/h ([GitHub limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)) | Worker only |
| 6 | CISA KEV and FIRST EPSS | Exploited in the wild? Exploitation probability? | One ~1.9 MB JSON file ([KEV](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json)); daily CSV ([EPSS](https://api.first.org/epss)) | Worker daily |
| 7 | Wayback and Software Heritage | Dead link → snapshot nearest the commit date ([Wayback API](https://archive.org/help/wayback_api.php)); archived repo | No key; SWH 120 req/h anonymous | Worker monthly |
| 8 | Stack Exchange (free key) and HN Algolia | Public discussion of the workaround or breakage | 10,000/day with key ([throttle docs](https://api.stackexchange.com/docs/throttle)); HN 10,000/h per IP ([HN API](https://hn.algolia.com/api)) | Worker, on Decision creation |
| 9 | Open web via the Claude API's `web_search`/`web_fetch` | Anything the above miss | Existing API key; $10 per 1,000 searches | Inline Quick Investigate or worker Deep Investigate |

The highest-value algorithm needs only rows 3 and 5 and is checkable end to end. Extract `github.com/{o}/{r}/issues|pull/{n}` URLs from commit messages, comments and npm deprecation strings. Read `state`, `state_reason` and `closed_at` from the issues endpoint ([GitHub Issues REST](https://docs.github.com/en/rest/issues/issues)). Find the fixing commit from the timeline. Then walk release tags in version order with `compare/{fixSha}...{tag}`. The first tag whose status is `ahead` or `identical` is the first release that contains the fix, as a live probe of the lodash compare endpoint confirms ([GitHub compare probe](https://api.github.com/repos/lodash/lodash/compare/4.17.20...4.17.21)). A `diverged` status falls back to searching the release body ([GitHub Releases probe](https://api.github.com/repos/psf/requests/releases/tags/v2.32.3)) or a Keep a Changelog `Fixed`/`Security` section ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/)) for the issue number. Compare results for a fixed SHA pair never change, so they can be cached permanently.

Several sources should be avoided. Reddit closed self-service API access on 11 November 2025, and anonymous `.json` calls returned 403 in testing ([r/redditdev mirror](https://r.datuan.dev/r/redditdev/s/gquSJqMgrM)). Maven Central applies network-level consumption limits with blocks of up to 30 days ([Sonatype 429 FAQ](https://central.sonatype.org/faq/429-error/)), so Maven metadata should come through deps.dev. NVD allows 5 requests per 30 seconds without a key ([NVD](https://nvd.nist.gov/developers/start-here)), which restricts it to keyed worker calls for CVSS or CPE detail. Bing's search APIs were retired on 11 August 2025 ([Microsoft](https://learn.microsoft.com/en-us/lifecycle/announcements/bing-search-api-retirement)), and Google's Custom Search JSON API is closed to new customers and ends on 1 January 2027 ([Google](https://developers.google.com/custom-search/v1/overview?hl=en)). Third-party search is 2–10 times cheaper than Claude's server search. Parallel ([pricing](https://parallel.ai/pricing)) and Perplexity Fast Search ([pricing](https://docs.perplexity.ai/docs/getting-started/pricing)) cost from $1 per 1,000 requests, Exa Lite costs $4 ([pricing](https://exa.ai/pricing)), and Tavily is the only provider confirmed to support published-date filtering ([Tavily](https://docs.tavily.com/documentation/api-reference/endpoint/search)). Rights to store results are mostly unpublished, though, and Brave allows storage only on a custom plan ([Brave](https://brave.com/search/api/)). These providers should wait until storage terms are confirmed.

### Nine node types extend the graph without APOC

Aura Free has no APOC, so all fetching and normalisation happens in Python and writes use plain `UNWIND $rows AS row MERGE` batches, matching how `cypher/21_record_decision.cypher` already records decisions. The additions attach to the existing `Dependency`, `Decision`, `Issue`, `ConfigKey` and `File` labels. Each external node carries `source`, `fetched_at`, `etag`, `license`, `tier` and `ingest_run_id`, so the UI can show attribution (CC BY-SA for Stack Exchange per [Stack Overflow licensing](https://stackoverflow.com/help/licensing), CC BY 4.0 for caniuse per [its licence](https://raw.githubusercontent.com/Fyrd/caniuse/main/LICENSE), MITRE's notice for CWE per [CWE terms](https://cwe.mitre.org/about/termsofuse.html)) and refresh conditionally.

| Node | Key properties | Relationships | Filled from |
|---|---|---|---|
| `Advisory` | `id` (GHSA/PYSEC/GO/RUSTSEC), `aliases`, `modified`, `severity`, `kev_added`, `epss`, `epss_date` | `(:Dependency)-[:AFFECTED_BY {introduced, fixed}]->(:Advisory)`, `(:Advisory)-[:HAS_CWE]->(:Weakness)` | OSV, KEV, EPSS |
| `Weakness` | `cwe_id`, `name` | ← `HAS_CWE` | CWE API, cached indefinitely |
| `PackageVersion` | `purl`, `published_at`, `is_deprecated`, `deprecated_reason`, `yanked`, `yank_reason`, `time_lag_days`, `version_lag` | `(:Dependency)-[:RESOLVED_TO]->(:PackageVersion)-[:BUILT_FROM]->(:Release)` | deps.dev, native registries |
| `Release` | `repo`, `tag`, `sha`, `published_at`, `body_hash` | `(:Release)-[:CONTAINS_FIX {method: compare\|changelog}]->(:ExternalIssue)` | GitHub Releases, compare |
| `ExternalIssue` | `url`, `state`, `state_reason`, `closed_at`, `fix_sha`, `etag`, `checked_at` | `(:Decision)-[:BLOCKED_ON]->(:ExternalIssue)`, `(:Decision)-[:CITES]->(:ExternalIssue)` | GitHub issues and timeline |
| `LifecycleCycle` | `product`, `cycle`, `eol_from`, `is_lts`, `is_maintained` | `(:Dependency\|:ConfigKey)-[:ON_CYCLE]->(:LifecycleCycle)`, `(:Decision)-[:TARGETS]->(:LifecycleCycle)` | endoflife.date |
| `ExternalLink` | `url`, `http_status`, `archived_url`, `swhid`, `checked_at` | `(:Commit\|:Comment\|:Document)-[:LINKS_TO]->(:ExternalLink)` | Wayback, Software Heritage |
| `WebSource` | `id` = hash(canonical URL + `retrieved_at`), `url`, `domain`, `tier`, `content_hash`, `quoted_spans`, `page_age` | `(:WebSource)-[:CONFIRMS\|CONTRADICTS {confidence, verifier}]->(:Decision)` | Investigate runs |
| `ResearchRun` | `id`, `question`, `mode`, `budget_usd`, `spent_usd`, `searches`, `status`, `steps` | `(:ResearchRun)-[:RETRIEVED]->(:WebSource)`, `(:ResearchRun)-[:ABOUT]->(:Decision)` | Investigate runs |

Four modelling rules keep the graph honest. External edges never trigger `SUPERSEDES`, which stays reserved for repo-internal evidence. A `CONTRADICTS` edge from a `WebSource` is shown next to the repo claim rather than merged into it. `WebSource` stores the hash and the short quoted spans, not full page bodies, because storage and reuse terms for most sources were not verified. `ResearchRun` records spend, so budgets are auditable.

### The worker fetches, Vercel reads, and only quick investigations run inline

A Python function on Vercel runs for up to **300 s on Hobby and 800 s on Pro**, with a 1,800 s beta ([Vercel duration docs](https://vercel.com/docs/functions/configuring-functions/duration)). GitHub-hosted Actions jobs can run for 6 hours ([GitHub Actions limits](https://docs.github.com/en/actions/reference/limits)). Untangle's worker currently uses 40-minute runs and one job per run. Many sources limit requests per IP, including GitHub anonymous (60/h), keyless Stack Exchange, HN Algolia, anonymous Software Heritage and Maven Central. The research notes infer, without verifying, that Vercel functions leave from shared cloud addresses, so other tenants could exhaust those budgets. Every per-IP-limited source is therefore worker-only. Vercel reads the graph and makes at most one or two single-item calls to CDN-cached APIs without stated limits: OSV `query`, deps.dev `GetVersion` and an endoflife.date product lookup. A new scheduled enrichment workflow refreshes OSV, KEV, EPSS, endoflife.date and open upstream issue state daily, Scorecard weekly to match its scan cadence ([Scorecard README](https://raw.githubusercontent.com/ossf/scorecard/main/README.md)), and Wayback and Software Heritage monthly. Stack Exchange and HN run when a Decision is created. The `GITHUB_TOKEN`, a free Stack Exchange key and an optional NVD key live only in Actions secrets, never in browser code or logs.

Investigations come in two tiers. **Quick Investigate** runs inside the existing FastAPI function. It streams progress over SSE with heartbeats, because HTTP/1.1 intermediaries can close idle connections, and it persists each step so a reconnecting client can resume the display. **Deep Investigate** becomes a job type in the existing durable job store, executed by the Actions worker. Vercel Workflows, GA since April 2026 with Python support, per-step retries and event-log resume, is the alternative ([Vercel background workers](https://vercel.com/kb/guide/background-workers-on-vercel)). Every step is idempotent, keyed by an evidence hash, and checked against a stored dollar and search budget before it runs. The Batches API halves token cost but is throttled for web search and has no fixed latency ([web search docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)), so it suits nightly enrichment and rationale extraction, not interactive questions.

### A quick investigation costs five to nine cents if it stays under 100k tokens

Haiku 5.5, Untangle's configured default (`src/untangle/llm.py`), costs **$0.10 per million input tokens, $0.01 for cache hits and $0.50 for output** on prompts up to 100,000 tokens. Above that threshold the request pays $0.50, $0.05 and $2.50, "even when part of its prompt is a cache hit" ([Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Web search adds $10 per 1,000 searches, and web fetch adds only token costs ([web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)). Both tools support Haiku 5.5, including dynamic filtering, which Haiku 4.5 lacks ([programmatic tool calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling)). The figures below are calculations from list prices, not measurements, and assume no model change, which only the user can authorise.

| Run type | Assumed workload | Fees | Tokens | Estimated total |
|---|---|---|---|---|
| Nightly structured enrichment, per repo | OSV batch, deps.dev batch, EOL, KEV, EPSS; ~30 upstream issues × (issue + timeline + ~8 compares) ≈ 300 GitHub calls | $0 | None | $0, plus worker minutes and ~30% of one hour's `GITHUB_TOKEN` budget |
| Rationale extraction, per hosted import | ~350 artifacts (50 PRs, 100 issues, ~200 decision-bearing commits) × ~2k input and ~300 output tokens | $0 | 0.7M in, 0.1M out | ≈$0.12 standard, ≈$0.06 batch; ~2× with a verifier pass |
| Quick Investigate (server tools) | `max_uses` 4 searches, 6 fetches capped at ~8k tokens each, ~10 loop iterations; tool-free synthesis; ~12 entailment checks | $0.04 | ~350k cumulative input (mostly cache hits), ~5k output | ≈$0.05–0.09 |
| Quick Investigate (third-party search) | 4 searches at $1/1k plus 6 extractions at $1/1k, client-side loop | ≈$0.01 | ~50k | ≈$0.015–0.03, pending storage-rights review |
| Deep Investigate | Lead plus 3 subagents, 15–20 searches, ~15× chat tokens | $0.15–0.20 | ~1.5M mostly cached input | ≈$0.20–0.40; hard cap $0.50 |
| Failure case | Uncached loop that crosses 100k tokens for ten iterations | $0.04 | ~1.1M at $0.50/M | ≈$0.55+ |

These estimates sit close to the open-source reference points. GPT Researcher reports about $0.40 per deep run ([GPT Researcher](https://github.com/assafelovic/gpt-researcher)). LangChain's open_deep_research spent $45.98 across 100 benchmark tasks with defaults ([open_deep_research](https://github.com/langchain-ai/open_deep_research)). Anthropic's own multi-agent system used about 15 times the tokens of chat, and token usage alone explained 80% of BrowseComp variance ([Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)). Four mechanical rules keep runs in the cheap regime. First, always set one `cache_control` marker, because server tool results get automatic cache breakpoints only when a request already has one ([tool use with caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching)). Second, never toggle web search or citations mid-run, since that invalidates the cache. Third, cap `max_uses` at 3–5 and `max_content_tokens` at about 8k. Fourth, compress findings into quote-anchored notes between requests instead of letting one turn accumulate every page. Two inputs remain unmeasured: the per-search token count is undocumented, and whether Haiku 5.5 uses the newer tokenizer, which produces about 30% more tokens, is unconfirmed. Both belong in the first eval run.

### Verification extends today's ID check to quotes, entailment and faithfulness

The current validator, `validate()` in `src/untangle/answer/compose.py`, accepts a model answer only if every `[id]` is in the retrieved evidence, there is at least one citation, the answer has at most five sentences, and every number of two or more digits appears in a cited source. That is strict on provenance but blind to whether the cited text *supports* the sentence. External evidence makes the difference much larger. Generative search engines fully supported only **51.5% of sentences** in a 2023 study ([Liu et al.](https://arxiv.org/abs/2304.09848)). Eight AI search engines answered more than 60% of news-citation queries incorrectly ([CJR Tow Center](https://www.cjr.org/tow_center/we-compared-eight-ai-search-engines-theyre-all-bad-at-citing-news.php)). Deep-research agents reach only **40–80% citation accuracy** ([DeepTRACE](https://arxiv.org/abs/2509.04499v1)). Frontier models still hallucinated about 30% of the time with web search on ([HalluHard](https://arxiv.org/html/2602.01031)).

The extension has five layers. The first keeps the evidence-set rule: every fetched page becomes a `WebSource` whose ID is the only citable handle, exactly as repo evidence is today. The second anchors every citation to an exact quote. Web search citations expose only the URL, title and up to 150 characters of `cited_text`, against an encrypted page body ([web search docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)), so they are acceptable for discovery but never as final citations. Final answers cite either `web_fetch` documents with citations enabled, which return full text with `char_location` offsets ([web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)), or self-supplied `search_result` blocks ([search results docs](https://platform.claude.com/docs/en/build-with-claude/search-results)). For the latter the API guarantees "valid pointers to the provided documents" ([Citations docs](https://platform.claude.com/docs/en/build-with-claude/citations)). Repo evidence and web evidence can then share one mechanism, with `source` set to an internal evidence URI or a web URL. Because Citations and structured outputs return a 400 when combined, the answer step parses citation blocks from text rather than using a JSON schema. The third layer checks entailment: each claim and its cited passage go through a yes/no judge, either a Haiku 5.5 call or a MiniCheck-class model that matches GPT-4 on grounding at about **400× lower cost** ([MiniCheck](https://arxiv.org/abs/2404.10774)), and unsupported claims are dropped or labelled unverified. The fourth layer tests faithfulness offline, because a correct citation is not a faithful one. Up to **57% of correct citations were unfaithful** in controlled tests, and the test principle is that adding irrelevant documents should not change attributions ([Wallat et al.](https://arxiv.org/abs/2412.18004)). The fifth layer handles source quality and disagreement. Rank the project repo first, then upstream repos and official docs, then advisory databases, then Q&A sites, then blogs, and enforce the top tier with `allowed_domains` on the first pass. Anthropic had to add similar rules after its agents favoured SEO content farms ([Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)). Normalise URLs to collapse mirrors. When web and repo disagree, show both, since deep-research agents proved "highly one-sided" on debate questions ([DeepTRACE](https://arxiv.org/abs/2509.04499v1)). If nothing survives verification, Investigate refuses or falls back to repo-only evidence with the existing refusal wording.

### Untrusted pages never share a request with private evidence or tools

Prompt injection is a design constraint. Even with Anthropic's improved safeguards, adaptive attackers succeeded **1.4–2.4% of the time** against browser agents, including 2.4% on Haiku 4.5 ([Anthropic](https://www.anthropic.com/research/prompt-injection-defenses)). No figure exists for Haiku 5.5 or for plain search and fetch. The web fetch docs warn that processing untrusted input alongside sensitive data creates exfiltration risk ([web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)), and OpenAI advises running public web search and private lookups in separate requests ([OpenAI guide](https://developers.openai.com/api/docs/guides/deep-research)). Untangle's pipeline should follow the plan-then-execute and dual-LLM patterns ([Beurer-Kellner et al.](https://arxiv.org/abs/2506.08837v3)) in four stages. In the plan stage, Untangle derives 2–4 queries from repo evidence before reading any untrusted text: package names and versions, error strings, and public issue URLs. In the research stage, a request sees only the question and those public identifiers, never Decision text or private evidence. It is limited by an ASCII-only `allowed_domains` list (Unicode homographs can bypass filters per the [server tools docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/server-tools)), `url_sources` that exclude client tool results, and a small `max_uses`. In the synthesis stage, a request with **no tools at all** joins repo evidence with already-fetched snippets wrapped as `search_result` blocks, so an injected instruction has no channel to act through. In the validation stage, the post-generation validator strips any URL outside the retrieval set, any instruction aimed at the user and any uncited sentence. Research mode is off by default for private repositories, because the queries themselves can leak identifiers to providers. Enterprise tenants who need zero data retention must set `allowed_callers: ["direct"]`, because dynamic filtering is not ZDR-eligible. Logs record URLs and domains, never secrets. In the UI, the feature should appear as "Investigate" and the evidence group as "Upstream evidence", with no model or provider names. Source links are always shown, which also satisfies the API rule that displayed outputs cite their original sources.

## Published methods turn Pulse's fixed weights into measurable signals

Pulse sums five boolean signals with fixed weights: contradiction 0.72, drift 0.16, ownership gap 0.14, rationale gap 0.11 and staleness 0.08 (`src/untangle/pulse.py`). Ownership gap means "no recent owner attached", and staleness means "older than the freshness window". The research literature supplies graded, testable replacements for each of these signals and for the extraction feeding them.

**Rationale extraction** is the largest data gap. Hosted imports call the pipeline with `llm_prs=0` (`src/untangle/repositories/worker.py`), so many decisions arrive without a "why". At the prices above, turning extraction on costs about 6–25 cents per import, so cost is a weak reason to leave it off. The literature shapes how to do it. A cross-artifact study found that commits and PRs mainly carry the GOAL, NEED and ALTERNATIVE sit more often in issues and PRs, and no single artifact type holds every component. Its ARGUS approach reached **51.4% precision and 93.2% recall** ([Sun et al. 2026](https://arxiv.org/abs/2604.10345)). LLM rationale for architecture decisions matched experts at only **0.267–0.278 precision** with 0.627–0.715 recall ([Zhou et al., TOSEM 2025](https://arxiv.org/abs/2504.20781)). LLMs extracting design decisions from commits drifted into implementation detail and frequently missed the rationale ([Karan et al. 2026](https://arxiv.org/abs/2609.03721)). The design implied is to over-generate, then filter. Join commit, PR and linked issue before extracting. Require a verbatim supporting quote and an exact span match. Run an entailment check. Give few-shot examples that separate decisions from implementation detail. Store rationale per component (GOAL, NEED, ALTERNATIVE, from the [Al Safwan and Servant taxonomy](https://people.cs.vt.edu/~khsaf/public/papers/fse19.pdf)), so the rationale gap becomes partial rather than boolean. The Linux OOM-Killer dataset gives sentence-level gold labels: it marks Decision, Rationale and Supporting Facts, and found rationale in **98.9% of commits** ([Dhaouadi et al., ICPC 2024](https://arxiv.org/abs/2403.18832); [Zenodo](https://zenodo.org/records/10063089)). Kantara-style conflict detection against past decisions is prior art for Untangle's contradiction signal ([Dhaouadi et al. 2025](https://arxiv.org/abs/2506.11005)).

**ADR status should count as a claim, not a fact.** Of 5,800 ADRs, about **63% were created already "accepted"**, skipping deliberation ([ICSA 2026](https://conf.researchr.org/details/icsa-2026/icsa-2026-papers/34/Architecture-Decision-Records-Adoption-Impact-and-Developer-Engagement-in-Open-Sou)). About half of repositories with ADRs hold only 1–5 records, which looks like a trial that was abandoned ([Buchgeher et al.](https://doaj.org/article/f838f2a538ea48e7a3b15ce99befe612)). An ADR accepted at creation with no corroborating code or config change should carry lower confidence. A long gap since the last ADR while decision-bearing commits continue is a staleness signal for undocumented decisions.

**Ownership gap and person-to-ask** should use the degree-of-authorship (DOA) truck-factor algorithm, which is open source and the standard baseline ([Avelino et al. 2016](https://arxiv.org/abs/1604.06766)), scoped per feature or decision subject rather than per repository. A decision is at risk when all of its DOA authors are inactive, which is the Files-at-Risk measure. Recommending by ownership alone concentrates knowledge and **raises turnover knowledge-loss risk by up to 65%**. The Sofia recommender spreads knowledge when files are at risk ([Mirsaeedi and Rigby, ICSE 2020](https://researchr.org/publication/MirsaeediR20)), and a reimplementation reported **28% fewer files at risk** ([Hajari et al.](https://arxiv.org/abs/2312.17236)). Person-to-ask should therefore rank by DOA plus review participation, discounted by recency, and add a "learner" candidate so each question doubles as knowledge transfer. Generative AI distorts truck-factor models ([arXiv 2507.08160](https://arxiv.org/html/2507.08160v1)), so lines carrying Entire or Agent Trace provenance should not count as a human owner's knowledge.

**Drift and "later patched"** signals should prefer explicit developer links, meaning `Fixes:` trailers, reverts (Untangle already has `REVERTS` edges) and "regressed by", over raw SZZ. SZZ variants sit at about **0.5 F1 on Linux** ground truth ([arXiv 2308.05060](https://arxiv.org/abs/2308.05060)), and LLM4SZZ reaches 0.588 ([arXiv 2504.01404](https://arxiv.org/abs/2504.01404)), so SZZ edges carry low confidence. Co-change association rules give the feature map a language-agnostic complement to static imports. ROSE predicted 26% of further changed files with 30% of suggestions correct ([Zimmermann et al., ICSE 2004](https://www.st.cs.uni-saarland.de/papers/icse2004/)). Those are modest figures, so they appear as "also-likely-affected" hints with support and confidence shown. Meta's two-stage incident ranking puts the root-cause change in the top 5 for **42%** of investigations ([Meta Engineering](https://engineering.fb.com/2024/06/24/data-infrastructure/leveraging-ai-for-efficient-incident-response/)). That is the template for the later incident use case: heuristic narrowing, then an LLM ranks the top k.

**Staleness should become evidence-based rather than age-based.** Technical lag has standard formulas: time lag is date(latest) minus date(used), and version lag is the major/minor/patch gap ([Decan et al., ICSME 2018](https://arxiv.org/abs/1806.01545)). Each dependency Decision can carry both at its `valid_from`, and vulnerability lag once OSV is joined. On-hold self-admitted technical debt marks code waiting for an external event ([Maipradit et al.](https://arxiv.org/abs/1901.09511)). Such comments become *superfluous* once the referenced issue is closed ([SCAM 2020](https://arxiv.org/abs/2009.13113)), which is a checkable definition for "this workaround can expire". Workarounds are the most common rationale in build-file debt, at 22% ([Xiao et al., TSE 2022](https://rebels.cs.uwaterloo.ca/papers/tse2022_xiao.pdf)), so comments in `package.json`, `pyproject.toml` and `pom.xml` deserve extra weight. Few-shot prompting with category descriptions beats zero-shot for debt classification, which suits a lower-cost model ([Sheikhaei et al.](https://arxiv.org/abs/2405.06806)). Advice about pins needs careful wording: pinning only direct dependencies is futile and can even be counterproductive compared with whole-graph lockfiles ([He et al., FSE 2025](https://arxiv.org/abs/2502.06662)).

**Temporal modelling** is ahead of most competitors already. `cypher/21_record_decision.cypher` records valid time (`valid_from`, `valid_to`) and transaction time (`created_at`, `expired_at`). One gap remains against the Zep/Graphiti design, which invalidates facts instead of deleting them ([Rasmussen et al.](https://arxiv.org/abs/2501.13956)). Re-ingest `SET`s a Decision's text, rationale and object in place, so a changed extraction overwrites what Untangle previously believed. Recording `ingest_run_id` and `extractor_version`, and versioning rather than overwriting when an extraction changes, would let Timeline answer "what did Untangle believe on date D" and audit extractor regressions. Contradiction detection can adopt Graphiti's rule: two facts on the same subject and predicate with overlapping validity and different values, and no `SUPERSEDES` edge between them, form a contradiction until a later commit or ADR explains it.

**The eval has to grow** from one repo and 25 questions into the product's main asset. No benchmark covers "why or when did this decision change" over commit history. SWE-QA and similar sets cover code understanding instead ([SWE-QA](https://arxiv.org/abs/2509.14635)), so an Untangle gold set would itself be a publishable contribution. Component gold sets already exist: OOM-Killer rationale labels, the ARGUS 63 commits, 100 architecture problems with expert rationale, the SZZ developer-informed oracle, and BUMP's 571 reproducible breaking updates ([BUMP](https://arxiv.org/abs/2401.09906)). BUMP can test a "broke the build, reverted, became a pin" chain extractor. For research mode, Anthropic began with about 20 real queries and one LLM-judge call ([Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)). Freezing fetched pages as BrowseComp-Plus does ([arXiv 2508.06600](https://arxiv.org/abs/2508.06600v1)) keeps the set reproducible and keeps the billed production checks cheap.

## Risks, open questions and figures that still need checking

The biggest market risk is that **Unblocked adds an explicit decision log**. It already claims obsoletion and conflict resolution and has the funding to build one. The countermeasure is to publish what Unblocked does not: refusal precision, as-of-date accuracy and citation accuracy on a public gold set. The biggest quality risk is extraction precision. At the 27–51% precision the literature reports, over-generated decisions would flood Pulse with false risks unless the quote, entailment and confidence gates ship *with* extraction rather than after it. External evidence brings its own noise. JFrog reported fabricated SQLite CVEs that were later rejected, and a CVE ID alone is not technical verification ([The Register](https://assets.theregister.com/2026/08/03/202615/)). This is another reason to prefer OSV's version events over free-text web claims.

Safety and cost risks are bounded but real. Prompt-injection success rates of 1–2% still represent meaningful risk at scale, and no figure exists for Haiku 5.5. Anthropic's measured research gains came from Sonnet- and Opus-class models: the average 11% accuracy gain from dynamic filtering on BrowseComp and DeepSearchQA was measured on Sonnet 4.6 and Opus 4.6 only ([Claude blog](https://claude.com/blog/improved-web-search-with-dynamic-filtering)). Research quality on a Haiku-tier model is therefore unmeasured, and the project rules leave any model upgrade to the user. The 100k-token price step can push a careless, uncached run from a few cents to more than half a dollar. Legal and data risks follow from storing evidence. Brave requires a custom plan to store results. Stack Exchange content is CC BY-SA with attribution and has disputed restrictions on LLM training. The licences of OSV, GHSA, KEV, ecosyste.ms and Libraries.io data were not verified. Storing quoted spans and hashes rather than page bodies limits exposure. Infrastructure limits shape the plan. Aura Free's capacity limits were not researched. The worker runs one job per 40-minute run. Per-IP quotas on shared egress are an unverified inference that still justifies worker-only fetching. Maven Central can block a network for up to 30 days. Untangle's current model of sharing imported evidence with every visitor works for public repos and blocks private ones.

Several open questions decide priorities and none has data yet. Which surface drives retention: MCP, PR bot, Slack or web? How accurate is Hinglish speech-to-text on technical KT calls? What do Indian IT services firms pay per transition today, and will they pay per transition? How often do PRs re-introduce superseded approaches, which the PR-guard case rests on? How many input tokens does one Claude web search add? Does Haiku 5.5 use the newer, more verbose tokenizer? Do conditional GitHub requests that return 304 count against the rate limit?

## Conclusion

Untangle's moat is a verification discipline, not a graph: every claim points at evidence it retrieved, and silence beats a guess. Applied to the internet, that discipline turns out cheaper than it looks. Most "research" about a codebase's upstream is a deterministic join against free APIs: an OSV `fixed` event, a GitHub compare status, an endoflife.date date. The expensive LLM web tier is needed mainly to discover links nobody recorded, and its output can be held to the same exact-quote standard as repo evidence. The resulting feature, "this workaround can be removed because upstream issue #N closed as completed and the fix shipped in tag T", is the most checkable claim a code-knowledge tool can make. It works naturally as PR-bot content, as dependency triage and later as CRA or VEX evidence.

Because the same cited, time-versioned graph serves coding agents from below and auditors from above, the build order matters more than the feature list. Measurement comes first, then cheap structured evidence, then agent and review surfaces, then tenancy, then compliance and handover products. The asset worth protecting throughout is a public number. If Untangle publishes refusal precision and as-of-date accuracy before Unblocked or GitHub do, it defines the category's quality bar instead of competing on connector count.
